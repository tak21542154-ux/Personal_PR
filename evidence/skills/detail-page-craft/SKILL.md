# 상세페이지 제작 (detail-page-craft)

> 공개용 정제본: 내부 경로·서버명·보안 점검 메모·호칭이 든 줄은 뺐고, 회사·사람 이름은 일반어로 바꿨습니다. 나머지는 원문 그대로입니다.

근거: hookable.ai 랜딩·블로그 4편 (2026-10-17 확인) + 로컬 ESE 파이프라인 `alpha_auto_poster` 실코드·주석 (라이브 사고 전례 포함). 출처는 맨 아래.

## 0. 핵심 원칙 — 모든 모드 공통

1. **구조보다 재료 먼저.** 막히는 지점은 "첫 화면에 무슨 말", "근거 자리에 뭘"이다. 재료 4요소(§1)를 먼저 한 장에 채우면 순서는 따라온다.
2. **근거 없는 형용사 금지.** 소구점마다 근거를 짝으로. "촉촉한 노른자" 옆엔 "정밀 온도 제어". 형용사만 있으면 해결·근거 블록이 같이 비어버린다.
3. **지어낸 값 금지.** 리뷰·스펙에 없는 수치·인증·치수는 쓰지 않는다. 없으면 "데이터 없음" 또는 생략. (ESE 코드 전체에 박힌 규칙 — §4)
4. **페이지 = 망설임 해소 순서.** 고객의 사기 전 의심(효과 있을까/과장 아닐까/나에게 맞을까/산 뒤 문제 없을까)이 풀리는 순서로 블록을 배치한다.
5. **모바일 우선.** 상세는 대부분 모바일에서 열린다. 첫 화면에서 스크롤 여부가 결정나고, 글자는 작은 화면 기준으로(쿠팡 가이드 18–24pt).
6. **남의 문구·배너 금지.** 도매처/타사 페이지의 문구 복제 금지, 남의 배너·쿠폰·로고 이미지 금지.

## 1. 재료 4요소 (기획은 여기서 시작)

| 항목 | 적을 것 | 가져오는 곳 |
|---|---|---|
| 타겟과 문제 | 누가 어떤 상황에서 이 제품을 찾는지 (인구통계 말고 상황으로) | 고객 문의, 리뷰, 검색어 |
| 소구점과 근거 | 왜 이 제품인지 + 그것을 증명할 자료. 소구점 2~3개로 추리고 근거를 짝으로 | 제품 스펙, 비교 대상, 실험 결과 |
| 후기와 인증 | 지금 확보된 후기, 인증, 보증 | 스토어 후기, 인증서, 검사 성적서 |
| 사진과 사용 장면 | 블록마다 보여줄 컷 목록 (있는 컷 / 찍을 컷 구분) | 촬영본 |

- 근거는 **원재료·제조 방식·비교 대상·수치**에서 가져온다. 예: 반숙란 — 무항생제 신선란(인증), 촉촉한 노른자(정밀 온도 제어), 담백한 맛(염분 조절).
- 후기는 **별점+사진 있는 것 몇 개**로 신뢰 블록 하나가 채워진다. 인증은 마크+인증번호까지.
- 첫 화면엔 제품 정면 컷, 해결 블록엔 특징 디테일 컷, 문제·공감 블록엔 쓰이는 장면.

## 2. 표준 구성 — 블록 순서

공통 블록: **첫 화면 → 문제와 공감 → 해결 → 근거 → 신뢰 → 구매 정보** (AIDA·5단계·9단계 구조가 결국 이 순서의 변주).

| 블록 | 하는 일 | AIDA 대응 |
|---|---|---|
| 첫 화면 | 무엇을 파는지 한눈에 (제품 컷 + 소구점 한 줄) | 주목 |
| 문제와 공감 | 고객의 상황을 먼저 말하기 | 흥미 |
| 해결 | 이 제품이 그 문제를 어떻게 푸는지 (소구점) | 욕구 |
| 근거 | 해결을 숫자·자료·비교로 뒷받침 | 욕구 |
| 신뢰 | 다른 사람의 평가와 인증 | 욕구 |
| 구매 정보 | 구성, 배송, 유의사항 | 행동 |

**뷰티/화장품은 망설임 4단이 더 구체적이다** (효능을 발라보기 전엔 확인 못 하는 상품이라 신뢰 블록을 뒤로 미루지 않는다):

| 블록 묶음 | 해소하는 의심 |
|---|---|
| 첫 화면 카피 · 구매 후기 | 정말 효과가 있을까 |
| 성분 근거 · 표현 각주 | 과장은 아닐까 |
| 추천 대상 · 사용법 · 문답 | 나에게도 맞을까 |
| 정보 고시 · 교환 안내 | 구매한 후 문제는 없을까 |

- 효능 문장마다 **표현 각주** 필수 ("원료적 설명에 한함", "건조함에 의해 약해진 피부 장벽·일시적 보습 효과에 한함"). 근거는 **화장품법 제13조** — 의약품 오인 표시·광고 금지, 위반 시 광고업무정지. 만족도 수치엔 "설문자의 주관적 의견" 단서.
- **기준색 = 제품 컬러**로 잡고 페이지 끝까지 유지. 배경이 바뀌어도 제품 컨테이너 색은 남긴다. 톤이 흔들리면 조각 이어붙인 페이지처럼 보인다.

## 3. 모드 A — 신규 기획·카피: AI 프롬프트 5단계

사람이 직접 페이지를 만드는 경우. 클로드(무료 Sonnet으로 충분)·ChatGPT·제미나이 어디서든 동작.

**사전 준비 (재료를 먼저 모은다):**

| 재료 | 어디서 | 없으면 |
|---|---|---|
| 고객 리뷰 | 스토어 리뷰, 인스타 댓글, 문의 내역 → 텍스트 파일 하나로 | 같은 카테고리 다른 상품 리뷰 (별점 2~3개가 장벽 재료) |
| 제품 정보 | 가격, 구성, 스펙 | 상품 등록 초안 |
| 배송·보장 | 출고 기준, 교환·반품, A/S | 쇼핑몰 정책 페이지 |
| 브랜드 한 줄 | 왜 만들었나 | 대표가 한 말 한 줄 |
| 보유 증거 | 후기 수, 평점, 인증 | 있는 것만, 없으면 비움 (지어내지 않음) |

**사용 규칙:** 리뷰는 대화창에 붙여넣지 말고 **파일로 첨부**. 프롬프트를 나눠 **한 대화에서 순서대로** — 앞 출력이 다음 입력이 된다. (쓰는 일과 검사하는 일을 한 프롬프트에 같이 시키면 검수가 사라진다.) 결과물 PDF로 받으려면 파일 생성 기능 켜기.

### (1) 리뷰 채굴

```
너는 구매심리 리서처다. 첨부한 파일은 [상품명] 관련 고객 리뷰 모음이다.
창작하지 말고, 고객이 실제로 쓴 표현을 그대로 인용해 아래 4가지를 추출하라.

추출 항목:
1. 구매 장벽: 사기 전 가장 망설인 이유(불안·의심·비교). 실제 인용 5개 이상.
2. 진짜 베네핏: 사고 나서 "이래서 좋더라"고 표현한 순간. 기능이 아니라 '생활이 어떻게 바뀌었나'. 인용 5개 이상.
3. 차별 포인트: 경쟁/대안 대비 다르다고 느낀 점. 인용 3개 이상.
4. 반복 표현: 여러 리뷰에 반복되는 단어·말투(헤드라인 후보). 빈도순 10개.

규칙:
- 출력은 4개 표. 각 행에 [고객 원문 인용] / [이게 의미하는 바] 두 칸.
- 추측·미사여구 금지. 리뷰에 근거 없는 내용은 "데이터 없음"으로 표기.
- 마지막에 "한 줄 인사이트: 이 고객들이 진짜 사는 이유는 ___" 한 문장으로 요약.
```

### (2) 골격 (Nik Sharma 5질문)

```
너는 DTC 상세페이지 기획자다. Nik Sharma '5질문 프레임'으로 페이지 골격을 짠다.
위 리뷰 채굴 결과와 아래 제품 정보를 바탕으로 5개 슬롯을 하나도 빠짐없이 채워라. 고객 언어를 우선 쓰고 지어내지 마라.

=== 제품 정보 ===
[가격 / 구성 / 스펙 / 배송·교환·보장 / 브랜드 한 줄]

각 슬롯마다 [헤드라인 1줄] + [본문 2~3줄] 작성:
① 이게 뭔 제품인가: 3초 안에 정체 파악
② 왜 사야 하나: 진짜 베네핏(리뷰 2번) 기반
③ 경쟁/대안과 뭐가 다른가: 차별 포인트(리뷰 3번) 기반
④ 이 브랜드는 왜 존재하나: 신뢰·공감 스토리
⑤ 주문하면 언제·어떻게 오나: 배송/교환/보장으로 마지막 불안 제거

규칙:
- 각 슬롯 헤드라인은 '고객 망설임(리뷰 1번)'을 하나씩 해소하도록 매칭. 어떤 망설임을 해소하는지 표기.
- 정보가 부족한 슬롯은 비우지 말고 "추가로 필요한 정보: ___"라고 질문하라.
출력: 슬롯별 표 + 페이지 위→아래 노출 순서 제안.
```

### (3) 검수 (할머니 테스트 + Harry Dry 3원칙)

```
지금부터 너는 두 명의 까다로운 검수관을 차례로 수행한다.
위 상세페이지 초안의 모든 헤드라인·핵심 문장을 검사하라.

■ 검수관 A: '할머니 테스트'
우리 할머니가 이 문장만 보고 '뭔 제품인지·왜 필요한지' 이해되는가?
- 전문용어/추상어/업계 표현을 전부 찾아 누구나 아는 말로 고친 [수정안] 제시.

■ 검수관 B: 'Harry Dry 3원칙'
모든 헤드라인을 1~5점 채점:
- Concrete(구체): 추상어 없는가 예) "생산적 루틴"❌ → "새벽 6시 글쓰기"⭕
- Visual(그림): 머릿속에 장면이 그려지는가
- Falsifiable(검증가능): 참/거짓 판별되는 단언인가 예) "최고의 품질"❌ → "3년 무상 A/S"⭕
평균 3점 이하 문장은 [개선안] 2개씩 제시.

출력:
1) 문제 문장 / 위반 원칙 / 개선안 표. 통과 문장은 'PASS'.
2) 마지막에 '검수 반영 최종 카피' 전체를 깔끔하게 다시 출력 (이게 다음 단계 입력).
```

```
①누구를 위한 제품 ②어떤 문제 해결 ③대안은 뭐 ④중요한 트레이드오프 ⑤추천 근거(평점·후기수)
4. JSON-LD: Product 스키마(name, description, brand, offers, aggregateRating, review) 초안.

출력: Brag Bar / FAQ / 보완 문단 / JSON-LD 코드블록.
```

## 4. 모드 B — 소싱 상품 등록: ESE 파이프라인 (`alpha_auto_poster`)

```
python prepare.py --source jsweet --limit 3        # 결과 확인 (제목·가격·이미지·상세)
```

`prepare.py`가 4종을 한 번에 묶는다 — 서로 어긋나면 안 되기 때문:

| 요소 | 담당 | 내용 |
|---|---|---|
| 제목 | `title_rules.py` | 도매처 이름 그대로 쓰면 규정 위반 → 우리 제목 생성 + 중복 제거 |
| 상세 HTML | `detail_template.py` + `copy_rules.py` | 이미지는 쓰되 문구는 우리 것 |
| 가격 | `pricing.py` | 마켓 수수료 + 최소판매가(1.5배) + 마진 15% 체크 |
| 안내 문구 | `wholesalers.py` | 반품기한·배송비 — **도매처마다 다름, 이 파일이 정본** |

**상세 섹션 순서** (`detail_template.build()`): 브랜드 표기(우리 이름) → 상품 이미지 → **SIZE 실측(가장 먼저·가장 크게 — 반품 감소 목적)** → DETAIL(소재·상세) → GUIDE(주문 전 확인) → 하단 브랜드.

**이미지 파이프라인:**
- `prepare.pick_images()` — 배너·쿠폰·플친·도매처 로고·안내문·공용 디자인 이미지 걸러냄 (최대 24장). 도매처 안내 이미지는 우리 안내와 내용이 달라 분쟁 씨앗.
- `scripts/split_tall_images.py` — 세로 6,000px 초과 '이어붙인 상세컷'은 3,000px 단위로 분할 후 우리 서버로 재호스팅 (13,224px 이미지가 구매자 화면에서 안 보이던 실고객 문의 사례. 마켓 렌더링 높이 한도는 문서 없음 → 보수적 3,000px).
- **업스케일 금지** — 860px cap은 원본 폭까지만. 270px 사진을 860px로 늘리면 3.2배 확대돼 뭉개진다.
- `scripts/audit_quality.py` — 썸네일 세로/가로 비율 3.0 초과(=상세페이지 통째 이미지) 걸러냄.

**마켓 제약 (검증된 것):**

| 마켓 | 제약 |
|---|---|
| 지그재그 | 이미지 한 변 **16,000px 이상** 또는 **가로/세로 비율 1.8 이상** 거부 (띠배너가 걸림). 월간 신규등록 상한 **1,000건**(월초 초기화, 2026-10-01 실측) |
| 스마트스토어 | 판매중 유지 상한 1,000건 (등급별 변동). 등록 즉시 판매중 |
| 쿠팡 | 상품한도 없음. 등록 후 승인요청 → 판매. 옵션(vendorItem) 단위 판매 on/off |

**절대 규칙 (어기면 라이브 사고 — 코드 주석에 전례 있음):**
1. 지어낸 치수·소재 금지 — specs에 없으면 안 씀. `text_sizes.py`는 항목 2개 이상 또렷하게 읽힐 때만 값을 돌려줌.
2. 도매처 문구 복제 금지 — `copy_rules.extract_facts()`가 사실만 뽑고 부정 표현은 걸러냄.
3. 배너·쿠폰·도매처 안내 이미지 금지 (`prepare._BAD_IMAGE`).
4. 이미지 확대 금지.
5. 기본 여성의류만 (`prepare.load()`) — 귀걸이·에코백 등 잡화 차단.

## 5. 플랫폼 규격 (2026-08 공식문서 교차확인)

| 플랫폼 | 상세 이미지 권장 가로 | 세로·용량 |
|---|---|---|
| 스마트스토어 | **860px** (공식 권장) | 4,000px 초과분은 3,000px까지만 우선 노출, 나머지 펼쳐보기 |
| 쿠팡 | **780px** (공식 권장) | 장당 세로 5,000px · 10MB 이하 · JPG/PNG. 글자 18–24pt 권장 |
| 토스쇼핑 | 규격 없음 (1,080px 통용) | 최대 50장 · 총 5MB 이하 |
| 지마켓·옥션 | 860px 통용 | — |
| 자체몰(카페24 등) | 스킨 본문 폭 | — |

**원칙:**
- 원본을 여유 폭(1,080px)으로 **한 번** 만들고 채널별 권장값으로 **줄여 내보내기**. 늘리면 흐려진다(줄일 때만 화질 유지).
- 세로는 한 장으로 길게 말고 **섹션 단위로 분할** — 로딩 가볍고, 채널별 교체 쉬움.
- 해상도는 DPI가 아니라 **가로 픽셀** 기준. 사진 위주=JPG, 글자·선 많음=PNG.
- 꼭 보여줘야 할 내용은 앞쪽 (스마트스토어 3,000px 노출 한도).

- [ ] 첫 화면만 보고 3초 안에 "뭘 파는지" 파악되는가 (제품 컷 + 한 줄)

- [ ] 글자 18pt+ / 모바일 미리보기 가독

- [ ] 도매처 문구 복제 0건 / 배너·쿠폰·남의 로고 0건
- [ ] 지어낸 수치 0건 (치수·인증·후기·판매량)
- [ ] 배송·교환 안내가 실제 정책과 일치 (`wholesalers.py` 정본)
